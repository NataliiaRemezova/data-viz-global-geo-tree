1. Loading the data

🛠 Fix 1 — robust field extraction. The original unlist()/as.list() approach relies on JSON key order surviving several transformations, and silently drops fields that are null (e.g. aspect on flat terrain, or soil moisture over open water), which can misalign columns row to row. Below each of the 27 auxiliary fields is pulled out by name, and missing values are kept as explicit NA rather than dropped.

Code 
root <- "path/to/GGT-10kEval-90"   # set this to your local extracted folder

aux_files <- list.files(
  root,
  pattern = "\\.auxiliary\\.json$",
  recursive = TRUE,
  full.names = TRUE
)

aux_vars <- c(
  "longitude", "latitude", "elevation", "slope", "aspect",
  "soil_moisture_0_5cm", "soil_moisture_5_15cm", "soil_moisture_15_30cm",
  paste0("bio", sprintf("%02d", 1:19))
)

read_one <- function(aux_path) {
  key <- basename(aux_path) |> str_remove("\\.auxiliary\\.json$")
  text_path <- file.path(dirname(aux_path), paste0(key, ".text.json"))

  aux   <- fromJSON(aux_path)
  label <- fromJSON(text_path)

  aux_row <- aux[aux_vars]
  aux_row[sapply(aux_row, is.null)] <- NA

  tibble(
    key     = key,
    level0  = label$level0,
    family  = label$level1_family,
    genus   = label$level2_genus,
    species = label$level3_species
  ) |>
    bind_cols(as_tibble(aux_row))
}

df <- map_dfr(aux_files, read_one)

If complete_frac is well below ~0.95, don’t reach for na.omit() reflexively — impute (e.g. median by family) or drop only the sparsest columns instead of the sparsest rows, since a handful of high-missingness columns (often aspect, sometimes slope on water/flat terrain) can otherwise cost you a large share of usable rows.

📝 Interpretation, revised against the actual rendered output. The hypothesis was that needleleaf would skew cold/dry, evergreen broadleaf warm/wet, deciduous broadleaf seasonal mid-latitude. The real boxplots show almost complete overlap across all three level0 classes on both annual_mean_temp and annual_precipitation — medians and IQRs sit on top of each other. Two things this points to:

  • This is not a bug — overlap is a genuine property of this curated subset. level0 is a very coarse 3-class label, and GGT-10kEval-90 was curated to balance Rare/Common/Frequent species counts, not climate coverage, so each broad category gets sampled across most of the planet’s climate envelope rather than occupying a distinct slice of it.
  • Annual mean temperature is also the wrong variable to expect separation on: deciduousness is a response to seasonality (shedding leaves for a cold or dry season), not to the annual average. A needleleaf conifer in Siberia and one in the Mediterranean can have very different annual means while both being needleleaf. temp_seasonality / isothermality are the more diagnostic variables — tested directly below instead of just eyeballing annual means.

vars_to_test <- c("annual_mean_temp", "annual_precipitation",
                   "temp_seasonality", "isothermality", "precip_seasonality")

purrr::map_dfr(vars_to_test, function(v) {
  kt <- kruskal.test(reformulate("level0", v), data = df)
  tibble(variable = v, kruskal_p = kt$p.value, statistic = unname(kt$statistic))
})

📝 Interpretation. Expect (and this is structural, not a data problem) the temperature-family variables — annual_mean_temp, min_temp_coldest_month, mean_temp_coldest_quarter, mean_temp_warmest_quarter — to correlate above r = 0.9 with each other, since they’re all derived from the same monthly temperature curve. Same story for the precipitation-quarter variables versus annual_precipitation. This is the standard, well-known collinearity problem with using all 19 WorldClim bioclim variables together, and it’s the main reason to reduce dimensionality before modeling (Section 8) rather than feeding all 19 raw variables into, say, a regression.

7. 💡 Idea: a decorrelated variable subset (VIF-based)

Rather than relying on PCA alone to absorb collinearity, it’s worth explicitly pruning to a smaller, less redundant variable set for any downstream interpretable modeling (e.g. “which climate variables predict level0?”).

Code 
# install.packages("car")
library(car)

full_model <- lm(annual_mean_temp ~ ., data = aux_corr |> select(-longitude, -latitude))
# iteratively drop the variable with the highest VIF until all VIF < 5
vif_prune <- function(data, threshold = 5) {
  repeat {
    v <- car::vif(lm(reformulate(setdiff(names(data), "target"), "target"),
                      data = data |> mutate(target = data[[1]])))
    if (max(v) < threshold) break
    data <- data |> select(-all_of(names(which.max(v))))
  }
  data
}

📝 A simpler, commonly used WorldClim subset to start from: bio01, bio02, bio03 (or bio04), bio12, bio15, bio18, bio19 — temperature mean/range/seasonality plus precipitation mean/seasonality/extremes, deliberately picked to span the two main axes (temperature, precipitation) without redundant quarter-level variables.

📝 Interpretation, against your actual numbers (PC1 = 41.6%, PC2 = 8.6%, cumulative to PC5 ≈ 67%). PC1 alone carries roughly 5x the variance of PC2 — consistent with Section 6’s finding that the temperature and precipitation variables both load together on PC1 (your loadings table shows annual_mean_temp, mean_temp_coldest_quarter, mean_temp_warmest_quarter and annual_precipitation, precip_wettest_month all near the top of PC1, not split across PC1/PC2 as a textbook “temperature axis vs. precipitation axis” would suggest). That means, for this specific dataset, PC1 is best read as a general “climate intensity / equability” axis rather than a clean temperature-only axis — likely because warm regions and wet regions overlap heavily in this particular sample (the tropics are both warm and wet, pulling those variables into the same direction). PC2 picks up the secondary signal — diurnal/seasonal range variables (temp_annual_range, mean_diurnal_temp_range, isothermality) rather than precipitation, i.e. a “stable vs. variable climate” axis.

Given Section 5’s finding that level0 barely separates on raw climate means, it’s unsurprising the colored-by-level0 scatter shows no visible clustering either — PC1/PC2 are summarizing real structure in the climate data, just not structure that happens to align with this particular coarse taxonomic label. The density-by-class plot above makes this concrete: if the three panels look like near-identical blobs in the same region of PC1/PC2 space, that confirms overlap rather than a plotting failure. Where to look instead: family-level summaries (Section 10, idea 1) or PC1/PC2 colored by family for just the top 5-6 most frequent families, which is a fairer test than three coarse classes that, by construction, span the whole planet.

9. t-SNE / UMAP for visual clustering 🛠 💡 📊

🛠 Fix 4. Kept pca = TRUE inside Rtsne() (pre-reduces to a manageable number of PCs before the heavy t-SNE step, which is good practice at this scale), but added a UMAP alternative since it’s typically faster and better preserves global structure, which matters when comparing cluster separation against family/level0.

🛠 Fix 6 — this is why no plot showed up in your render. The chunk was left as eval: false as a placeholder in the first draft and I never flagged it clearly enough — that’s on me, not a data problem. It’s switched on below. For datasets above a few thousand rows, t-SNE gets slow fast; a random subsample keeps this responsive without changing the qualitative picture.

📝 Comment. Rerun t-SNE with at least 2–3 perplexity values (e.g. 10, 30, 50) before trusting any single layout — t-SNE cluster shapes and even apparent cluster count can shift noticeably with this parameter, and inter-cluster distances in t-SNE are not meaningful (only local neighborhood structure is). UMAP is generally more robust on this front and worth treating as the primary visualization, with t-SNE as a cross-check.

11. Summary

  • The original script’s hard crash was a single corrupted pipe character; a second, separate bug (select(-sample_id)) would have surfaced right after fixing the first.
  • Dimension reduction is still well-justified — the 19 bioclim variables are highly collinear by construction (Section 6), so PCA genuinely compresses redundant information. But on your real data, PC1 turned out to be a mixed “climate intensity” axis (temperature and precipitation together) rather than a clean temperature-only axis — worth stating as a finding rather than assuming the textbook split.
  • The headline real finding is a negative result, and it’s a legitimate one: level0 (deciduous/evergreen broadleaf/evergreen needleleaf) does not separate cleanly on climate in this curated 90-species sample — not on raw boxplots, not on the PCA scatter, and (check your own re-render) likely not strongly on UMAP either. That’s not a failed analysis; it’s evidence that this particular 3-class label, in this particular balanced-rarity sample, isn’t primarily a climate signal.
  • The more promising next step demonstrated in Section 10 is dropping to family-level granularity, where niche breadth varies enough to be worth reporting on its own. If you want to push further: repeat Section 10’s family table on the 300- or 900-species eval splits, where more samples per family will make the niche-breadth ranking more stable.
